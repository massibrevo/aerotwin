# UX and mode semantics

Nine durable routes share a local sidebar and a historical dataset selector. Navy/slate surfaces, restrained cyan and amber data-class badges distinguish layers. System fonts, labeled native controls, focus styles, keyboard aircraft selection, loading/error/empty states and responsive stacked layouts support usability. No formal accessibility certification is claimed.

Normal distribution uses a single local server and compiled frontend. The new /guide route provides an Italian walkthrough. Import/training controls in Data & experiments perform actual local work with errors and durable job states. First launch is always offline synthetic demo. Users explicitly enable live positions or online map tiles. A provider error remains LIVE-unavailable, with an explanatory message and empty positions. Offline map is bundled public-domain geometry. Online map is optional MapLibre/OpenFreeMap; errors/timeouts return to offline geometry. Track rotates aircraft; list/map use the same filters. No interpolation is claimed.

Replay uses a fixed BCN synthetic recording independently of the chosen region. History date/search/origin filters affect table and export; charts explicitly summarize the full dataset. Radar mode/geography and historical dataset/model are independent layers. Schedule counts, aircraft observations and hypothetical queue results must never be conflated.

Version 0.3 applies a new light/dark multi-colour workspace, command navigation, increased typography and a full-height map-first radar. The default radar basemap is free OpenFreeMap/OSM streets, independent of the synthetic/live aircraft mode. Offline remains selectable and automatic on map failure. Read radar-ui-v0.3.md for complete interaction and trail semantics.
